# Обновление УСО-32 по USB CDC

Реализация относится только к `uso_emb` (PlatformIO). Остальные проекты в корне
не изменялись и с этим протоколом загрузчика не совместимы.

## Команды основной программы

INFO и BOOT доступны в состоянии ожидания: после включения и после STOP.
Во время потока обе команды игнорируются без ответа. Весь ключ BOOT потребляется
парсером даже во время потока, его байты не выполняются как отдельные команды.

| Запрос | Ответ | Действие |
|---|---|---|
| `A1` | `A1 <ASCII-строка> 00` | Дата, время сборки, имя прошивки |
| `08 12 34 56 78` | `08 AA` | Перезапуск в загрузчик |

Пример INFO: `A1 "Oct 29 2026 15:10:00 USO32_App_v2.0" 00`.
Дата/время — фактические `__DATE__`/`__TIME__` компиляции, а не часы платы.
Терминатор NUL обязателен. Ключ передаётся в указанном порядке, старший байт первым.
Неправильный/неполный ключ не вызывает переход. Полная команда должна прийти за
100 мс; после тайм-аута её можно отправить заново. Ответ BOOT именно `08 AA`.

Ответ помещается в очередь целиком. МК ждёт завершения USB IN, отключает USB на
100 мс, записывает одноразовый маркер в зарезервированную RAM и делает system reset.
До завершения передачи новые команды не выполняются; USB reset/suspend отменяет
ожидание перехода. Маркер принимается
только после программного сброса и немедленно очищается загрузчиком.

## Размещение памяти

| Область | Адрес | Размер |
|---|---|---:|
| Загрузчик | `08000000–08007FFF` | 32 КБ |
| Основная программа | `08008000–0801F7FF` | 94 КБ |
| Метаданные образа | `0801F800–0801FFFF` | 2 КБ |
| Маркер reset в RAM | `20007FF8–20007FFF` | 8 байт |

Оба linker script исключают маркер из стека и BSS. VTOR основной программы
устанавливается на `08008000` в SystemInit. Загрузчик использует HSI16/PLL (144 МГц)
и HSI48/CRS для USB; внешний генератор не требуется. АЦП удерживается в RESET.

При обычном включении загрузчик даёт **3 секунды** для подключения консоли, затем
запускает проверенную программу. INFO или корректный кадр UBL1 оставляет его в
режиме загрузчика. После команды BOOT из приложения или при отсутствии корректного
образа загрузчик остаётся в этом режиме без ограничения времени.

## Первоначальная установка через ST-Link

```powershell
cd C:\Projects\AI\USO32\uso_emb
python -m platformio run
python scripts/export_firmware.py
```

Для первой установки записать **`dist/uso32_factory.hex`** через STM32CubeProgrammer
и выполнить reset. Он содержит загрузчик, основную программу и метаданные.
Вариант BIN: `dist/uso32_factory.bin` по адресу **`0x08000000`**.
Это заменяет прежнюю прошивку без загрузчика; первое обновление старой версии
через USB невозможно, поскольку она не имеет этих команд и новой разметки Flash.

`dist/uso32_bootloader.hex` устанавливает только загрузчик, затем приложение
записывает консоль по USB. При установке только загрузчика на плату со старой
программой предварительно стереть Flash через программатор.
`dist/uso32_g431.bin` — **только приложение**, линкованное по `0x08008000`.
Его нельзя записывать по `0x08000000` и нельзя передавать загрузчику factory.bin.
Прямая SWD-запись одного приложения не обновляет метаданные; используйте factory
для SWD или приложение для USB.

Option bytes: `nSWBOOT0=0`, `nBOOT0=1`, как в основном README. Загрузчик не меняет
option bytes и не обновляет самого себя. USB-запись ограничена областями приложения
и метаданных. Аппаратная WRP-защита загрузчика автоматически не включается.

## Консоль ПК

Готовая программа Windows: `dist/uso32-bootloader.exe` (Python не нужен).
Исходник: `tools/uso_bootloader.py`, зависимость `pyserial==3.5`.

```powershell
.\dist\uso32-bootloader.exe list
.\dist\uso32-bootloader.exe --port COM5 info
.\dist\uso32-bootloader.exe --port COM5 enter
.\dist\uso32-bootloader.exe --port COM5 flash .\dist\uso32_g431.bin
.\dist\uso32-bootloader.exe --port COM5 flash .\dist\uso32_g431.bin --no-run
.\dist\uso32-bootloader.exe --port COM5 run
```

Для Python заменить `.\dist\uso32-bootloader.exe` на `python tools/uso_bootloader.py`.
Для сборки EXE:

```powershell
python -m pip install pyinstaller pyserial
.\scripts\build_console.ps1
```

Перед `info`, `enter`, `flash` поток должен быть остановлен командой STOP.
Консоль не останавливает измерение автоматически. Закрыть порт в других программах.
`flash` проверяет файл и параметры устройства **до стирания**, при необходимости
переводит приложение в загрузчик, переподключается, пишет, проверяет CRC и запускает
программу. Порт выбирается явно; другие устройства не перебираются. После reset
ищется прежний USB serial number; если его нет — прежнее имя порта. Для ручного
выбора нового имени добавить `--boot-port COM6`. Несовпадающий serial не допускается.
У приложения и загрузчика одинаковый serial из UID МК и VID/PID; имя продукта различается.

Код выхода: 0 — успех команды, 1 — ошибка, 130 — прерывание пользователем.
Успешный RUN означает ACK запуска, а не проверку аналогового тракта.
Ошибка/обрыв обновления требует повторного `flash`; старая программа после начала
стирания не сохраняется, но загрузчик остаётся доступным.

## Протокол загрузчика UBL1

Загрузчик также отвечает на одиночный `A1` строкой `USO32_Boot_v1.0` с датой/временем.
Остальной обмен — бинарные кадры. Все многобайтовые поля ниже **little-endian**,
в отличие от ключа входа BOOT.

Запрос: `"UBL1" | cmd:u8 | seq:u16 | len:u16 | payload[len] | crc32:u32`.
Ответ: `"UBR1" | (cmd|80):u8 | seq:u16 | len:u16 | status:u8 | data | crc32:u32`.
`len` ответа включает status. CRC32/ISO-HDLC (как `zlib.crc32`) покрывает весь
кадр до самого CRC, включая magic, команду, seq и длину. Max payload — 260 байт.
Тайм-аут неполного кадра — 1 с; неверный CRC/длина не вызывает Flash-операций.
Хост ждёт ответ до 10 с, при потере повторяет тот же кадр с тем же seq до трёх раз.
Загрузчик хранит последний запрос/ответ: точный повтор получает прежний ответ
без повторного стирания/записи. Другие байты с тем же seq отклоняются.
Обмен последовательный: следующий запрос после ответа.

| cmd | Запрос payload | Ответ data при status=0 |
|---|---|---|
| 01 HELLO | пусто | version:u8 (=1), app_base:u32, app_max:u32, page:u32, chunk:u32, valid:u8 |
| 02 BEGIN | image_size:u32, image_crc32:u32 | пусто |
| 03 WRITE | offset:u32, 1…256 байт | следующий offset:u32 |
| 04 FINISH | пусто | пусто |
| 05 RUN | пусто | пусто |

BEGIN сначала стирает метаданные, затем 47 страниц приложения. WRITE разрешён
после BEGIN, последовательно с offset=0, выравнивание по 8 байтам; неполный
doubleword разрешён лишь в конце образа и дополняется FF. Адрес вычисляет загрузчик.
Проверяются запись и границы без переполнения. FINISH требует все данные, проверяет
CRC, MSP и Thumb reset vector в пределах образа; затем пишет размер/CRC и отдельным
последним doubleword — признак завершения. При каждом запуске эти проверки повторяются.
ECC-ошибка при чтении незавершённой Flash-записи делает образ невалидным.

Status: 0 OK; 1 неверный запрос; 2 неверное состояние; 3 границы/порядок/длина;
4 Flash; 5 CRC образа; 6 векторы. USB reset/suspend сбрасывает сессию передачи,
незавершённый образ не запускается; после переподключения нужно повторить BEGIN.
CRC проверяет повреждения, но не криптографическую подлинность прошивки.

Метаданные (16 байт): `size:u32, crc32:u32, magic:u32=32534F55, version:u32=1`.
Остаток страницы FF. Factory.bin использует тот же формат.

## Проверки

```powershell
python -m pip install ziglang scipy
python tests/test_core.py
python tests/test_bootloader.py
```

Тест загрузчика выполняет настоящий C-код парсера/обновления с моделью Flash,
подключённой к настоящему Python-клиенту. Проверяются фрагментация USB, потеря ACK,
повтор команд, неправильный CRC, границы, неполная запись, сброс и ошибки на разных
этапах Flash, включая последнюю запись признака завершения.

На плате ещё нужно проверить перечисление USB и смену COM, ACK до reset, 3-секундное
окно восстановления, переход VTOR/MSP и отключение питания во время обновления.
Программная симуляция эти аппаратные испытания не заменяет.
Организация Flash сверена с [ST RM0440, category 2](https://www.st.com/resource/en/reference_manual/dm00355726.pdf).

## Проверка на NUCLEO-G431KB без внешних 4,608 МГц

Отдельная стендовая сборка использует HSI16/PLL 144 МГц для процессора и
HSI48/CRS для USB. Основная сборка УСО с общим внешним генератором сохранена.

```powershell
python -m platformio run -e uso_nucleo_hsi -e uso_bootloader
python scripts/export_firmware.py --nucleo
```

Записать `dist/nucleo/uso32_factory.hex` через ST-Link. Это полный образ с
загрузчиком и метаданными. На физической плате эта сборка пока не проверена.
USB CDC прошивки использует PA11 (D−), PA12 (D+) и общий GND; USB-разъём
встроенного ST-Link предоставляет отдельный ST-Link VCP, не USB CDC приложения.
Без ADS1262 приложение показывает ошибку АЦП, но INFO и BOOT остаются доступны.
Для измерений нужны ADS1262, его штатный тактовый сигнал и подключения из README.
