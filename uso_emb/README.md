# УСО-32 / STM32G431KBU6 / ADS1262

Прошивка платы Rev P из `../data`, целевой МК подтверждён пользователем:
STM32G431KBU6, 128 КБ Flash. Связь — встроенный USB Full Speed CDC, питание USB.
Это исходный проект для платы, а не для разводки Nucleo: профиль Nucleo в PlatformIO
используется только для выбора того же кристалла, startup и linker script.

Версия 2.0 добавляет INFO (`A1`) и вход в отдельный USB-загрузчик
(`08 12 34 56 78` → `08 AA`), только при остановленном потоке.
**Новая разметка Flash:** приложение начинается с `0x08008000`.
Первоначальная установка, консоль ПК и протокол обновления — [BOOTLOADER.md](BOOTLOADER.md).

## Сборка и загрузка

```powershell
python -m pip install platformio==6.2.0
cd C:\Projects\AI\USO32\uso_emb
python -m platformio run
python scripts/export_firmware.py
```

Первоначальная загрузка `dist/uso32_factory.hex` выполняется по SWD через ST-Link
в STM32CubeProgrammer. Последующие обновления — консолью USB из BOOTLOADER.md.
Проект собирается без CubeMX:
PlatformIO устанавливает GCC, CMSIS, STM32CubeG4 и USB Device Library.
Файлы после сборки: `.pio/build/uso_g431/firmware.elf`, `firmware.bin`.
Готовое приложение находится в `dist/uso32_g431.bin`, `.hex`, `.elf`;
загрузчик — `dist/uso32_bootloader.*`; единый установочный образ — `dist/uso32_factory.*`.
`dist/manifest.json` содержит SHA-256 образов и исходников. После изменения кода
пересобрать и обновить эти копии: `python scripts/export_firmware.py`.
Адрес загрузчика/factory: `0x08000000`, приложения: `0x08008000`.
Прошивка не меняет option bytes автоматически.

Перед запуском платы с подтяжкой PB8 вверх нужно выбрать загрузку из main Flash
независимо от PB8/BOOT0: `nSWBOOT0=0`, `nBOOT0=1` в STM32CubeProgrammer
(ST AN5094, таблица 6). Сохранить остальные option bytes. Доступ SWD — PA13/PA14,
NRST и GND; учитывать питание платы от USB при подключении программатора.

Используемые USB VID/PID `0483:5740` — распространённые значения примера ST для
локальной разработки. Для серийного устройства назначить собственные разрешённые
идентификаторы через `USO_USB_VID/USO_USB_PID` в `platformio.ini`. Старый драйвер
«USO-COM» из фотографии не приложен; совпадение его VID/PID и совместимость
прикладной программы с новым USB устройством не установлены. Современная Windows
обычно использует системный CDC-драйвер `usbser`.

## Подключение и тактирование

| Функция | Вывод МК | Настройка |
|---|---|---|
| ADS1262 CS | PA15 | GPIO, высокий в покое |
| ADS1262 SCLK / MISO / MOSI | PB3 / PB4 / PB5 | SPI3 AF6, mode 1, MSB first |
| ADS1262 DRDY | PB6 | EXTI6, спад |
| ADS1262 START | PA8 | постоянно низкий, управление командами SPI |
| ADS1262 RESET/PWDN | PB7 | низкий при старте и аппаратной ошибке |
| USB D− / D+ | PA11 / PA12 | выделенная функция USB, GPIO analog/no pull |
| Статус | PA0 | LED активен высоким уровнем |
| Тактирование МК | HSI16 | PLL M=4, N=72, R=2; 144 МГц |

SPI3: 2,25 МГц. USB: HSI48/CRS. АЦП: внутренний генератор 7,3728 МГц,
XTAL1/CLKIN на DGND, XTAL2 не подключён; внешний генератор не нужен.
AIN8/AIN9 (INPMUX=89), внутренняя опора, PGA ×1…×32, Sinc4 (MODE1=60),
MODE2=08 | gain<<4, CHOP выключен: номинально 400 отсчётов/с.
POWER=03 включает VBIAS и опору, очищает RESET (в отчёте POWER=13 сохранял RESET).
ACM около 2,5 В, не соединять с GND. A8 и A9 подтянуты к ACM через 91 кОм.
Перемычку A8–A9 снять перед измерением внешнего сигнала.

Инициализация проверяет ID и чтение записанных регистров. При запуске выполняется
самокалибровка смещения для всех шести усилений с `INPMUX=FF`; результаты хранятся
в RAM и восстанавливаются при START. Вход после калибровки возвращается на `89`.
Динамические выделения памяти приложением не используются; USB класс получает
статический буфер.

## Протокол

Порт: 57600, 8N1. Для USB CDC line coding принимается, но не задаёт физическую
скорость USB и не меняет частоту АЦП. DTR не является условием запуска.

| Передаваемые байты | Действие | Ответ |
|---|---|---|
| `AA` | CBUSY, запрос готовности | `55`, если АЦП исправен |
| `66` | Чтение номера УСО (классическая «Проводка») | `01 NN 00 00 FF` |
| `71` | SET_HP | нет |
| `72` | CLR_HP | нет |
| `20+g`, `freq` | START, 24 бита | поток 5-байтовых кадров |
| `90+g`, `freq` | START, 32 бита | поток 6-байтовых кадров |
| `10` | STOP | `55` после остановки |
| `A1` | INFO, только вне потока | `A1`, дата/время/название ASCII, `00` |
| `08 12 34 56 78` | BOOT, только вне потока | `08 AA`, затем загрузчик |

`NN` — однобайтовый номер устройства, по умолчанию 1. Задаётся при сборке
через `USO_DEVICE_NUMBER` в `include/uso_config.h` или флагом
`-D USO_DEVICE_NUMBER=42` (допустимо 1…255; ноль «Проводка» считает отсутствием
идентификации). Это назначаемый номер, не уникальный UID микроконтроллера.
Два неиспользуемых старым клиентом байта ответа заполнены нулями.
Запрос `66` не требует предварительного `AA`, работает также при ошибке АЦП
и во время потока: ответ ставится в общую очередь между полными кадрами.
Для поиска устройства классической «Проводкой» используйте остановленный поток.
Внутри незавершённой START или BOOT байт `66` остаётся параметром этой команды.

**START — два байта**, как подтвердил пользователь. `g=0…5` означает
×1, ×2, ×4, ×8, ×16, ×32. Например, `95 03` — 32 бита, ×32, ФНЧ 9 Гц.
Частотный байт должен прийти менее чем через 100 мс после командного.
В ожидании `freq` байт `10` означает ФНЧ 11 Гц, а не STOP. Для отмены неполной
команды дождаться 100 мс, затем отправить STOP. Неверная пара отбрасывается целиком.
Неизвестные команды не имеют ответа. Каждая полная START перезапускает АЦП и
состояния цифровых фильтров. SET_HP/CLR_HP можно посылать во время потока;
переключение сбрасывает только состояние ФВЧ и может создавать переходный процесс.

| freq | ФНЧ, Гц | freq | ФНЧ, Гц |
|---|---:|---|---:|
| 00 | 20 | 10 | 11 |
| 01 | 15 | 11 | 8 |
| 02 | 12 | 12 | 6 |
| 03 | 9 | 13 | 4 |
| 04 | 6,5 | 14 | 3 |
| 05 | 4,3 | 15 | 2,5 |
| 06 | 3 | 16 | 2 |

Кадры: `00 D3 D2 D1 FF` (24 бита) или `00 D3 D2 D1 D0 FF` (32 бита).
Данные в дополнительном коде, старший байт первый. 24-битный режим передаёт
старшие 24 бита отфильтрованного 32-битного кода, без округления. Это выбранное
толкование документа, в котором точное правило сокращения разрядности не задано.
Маркеры могут встречаться внутри данных: читать по длине, не искать первый `FF`.
USB может объединять/делить кадры произвольным образом. При STOP удаляются ещё
не отправленные отсчёты; уже переданный USB пакет может предшествовать `55`.
Во время потока ответ CBUSY также встречается между полными кадрами; утилита
захвата поэтому запрашивает готовность только до START.

Напряжение после фильтрации: `code * 2.5 / (2^(bits-1) * gain)` В.
Ограничение входа ±2,5 В не означает такой диапазон при ×32: его полная шкала
±78,125 мВ. Автоматическое переключение PGA не выполняется, усиление выбирает ПК.

## Фильтрация и отличия от исходных материалов

ФНЧ — Butterworth 10-го порядка, пять SOS-секций, double; −3,0103 дБ на заданной
частоте и асимптотический спад около 60 дБ/октаву. Это выбранная характеристика,
поскольку фотография задаёт частоты и крутизну, но не тип фильтра. Коэффициенты
зафиксированы в `src/filter_coeffs.inc`, генератор — `scripts/generate_filters.py`.
Фильтр работает в кодах АЦП, выход округляется и насыщается до int32.
Переходный процесс после START передаётся в поток, отсчёты не скрываются.
Указанный в PDF фиксированный КИХ 127 taps/25 Гц не реализует эти 14 полос:
приоритет здесь имеет протокол УСО-32. FMAC и FFT не используются; связанного
файла `ads1262_fir_stm32g431_f301.c` в исходных данных нет.

ФВЧ — **предварительный первый порядок, 0,1 Гц**, по согласованию с пользователем.
Это DC-blocker; точная коррекция «земляного наклона» не может быть восстановлена
без передаточной функции оригинального устройства. Частота задаётся в
`include/uso_config.h`. После питания ФВЧ выключен.

PDF сам отмечает, что разделы кроме исправления питания не проверялись.
В прошивке исправлены следующие места:

- MODE0=00: CHOP выключен; номинальная скорость 400 Гц.
- POWER=03: VBIAS и опора включены, RESET очищен.
- EXTCLK=0 обязателен; внешний тактовый сигнал и аварийные флаги отвергаются.
- Самокалибровка использует отключённые входы `INPMUX=FF`, CS удерживается низким,
  есть тайм-аут. При смене усиления применяется STOP/START, не один START.
- Checksum — сумма четырёх байтов данных + `9B`; статус в сумму не входит.
- Требование ответа менее 100 мкс из фотографии **не гарантируется через USB CDC**:
  задержку определяет планирование USB и ОС. Для ПК использовать тайм-аут не менее
  100 мс. Настройка COM 57600 не устраняет это ограничение.

Документация для проверки:
[TI ADS1262 SBAS661C](https://www.ti.com/lit/ds/symlink/ads1262.pdf),
[ST STM32G431KB](https://www.st.com/en/microcontrollers-microprocessors/stm32g431kb.html),
[ST AN5094](https://www.st.com/resource/en/application_note/an5094-migrating-between-stm32f334303-and-stm32g431g474g491-mcus-stmicroelectronics.pdf).
Исходники ST подтягиваются PlatformIO со своими лицензиями.

## Ошибки и проверка на плате

Счётчики `uso_stats` доступны через SWD: checksum, статус/ошибки SPI, пропуски DRDY,
переполнение USB очередей, неизвестные команды и тайм-ауты. При ошибке АЦП,
потере тактирования или пропуске DRDY поток останавливается,
RESET АЦП удерживается низким, CBUSY больше не отвечает `55`. Для восстановления
нужен reset МК/переподключение питания. STOP отвечает `55` и в этом состоянии.
МК и АЦП работают от отдельных внутренних генераторов. Отсутствие DRDY
обнаруживается по тайм-ауту; USB доступен при ошибке АЦП.
USB reset/suspend останавливает поток; после возвращения нужен новый START.
LED: постоянно включён в ожидании, 1 Гц при приёме, 5 Гц при ошибке.

```powershell
python -m pip install ziglang scipy pyserial
python tests/test_core.py
python tools/capture.py COM5 --gain 1 --freq 0x00 --bits 32 --seconds 10 --output capture.csv
```

Тесты компилируют фактический переносимый C-код и сравнивают фильтрацию с независимым
SciPy-эталоном. Проверка 29.10.2026: обе ARM release сборки успешны, 8 тестов ядра
и 12 тестов загрузчика прошли
(168 комбинаций START, ошибочные частоты/тайм-ауты, checksum/статус, знаковые
границы и кадры, все 14 фильтров, подавление DC и насыщение).
До подключения платы невозможно подтвердить USB enumeration,
качество сигнала, скорость DRDY и электрическую корректность схемы. При первом
запуске проверить питание, VBIAS, USB COM, `AA → 55`, 400 Гц на DRDY, все
усиления/полосы, STOP и отключение USB. Проверить, что при отключении DRDY и
перегрузке входа приём прекращается, а не продолжается с некорректными данными.
В CSV время номинальное `n/400`; аппаратных меток времени исходный протокол не имеет.

## Восстановление после остановки чтения ПК — v2.2

Переполнение очереди передачи USB останавливает АЦП командой STOP1 и удаляет
ожидающие отправки отсчёты. Калибровка и готовность сохраняются, если STOP1
выполнен успешно. AA снова отвечает 55; новый START запускает новую запись.
Уже переданный USB-пакет и данные в буфере Windows могут остаться: программа ПК
должна отправить STOP, дочитать ответ 55 и очистить входной буфер перед новой
записью. Автоматического продолжения потока с потерянными отсчётами нет.
Переполнение входной очереди команд также завершает текущую сессию без сброса
исправного АЦП. Счётчики переполнений сохраняются для диагностики.
Ошибки SPI/АЦП, контрольной суммы, пропуски DRDY и тайм-ауты остаются фатальными.
