# УСО-32 Dual-Mode Protocol V2 (USO-NG) — Архитектура и спецификация

## 1. Обзор и совместимость

Прошивка **`USO32_App_v3.0_DualV2`** для платы **Rev P (STM32G431KBU6 + TI ADS1262)** реализует двухрежимный обмен с **автоматическим определением протокола**:

| Клиент ПК | Поведение УСО | Совместимость |
|---|---|---|
| **Старая «ПРОВОДКА»** | Получает стандартные однобайтовые/двухбайтовые команды (`AA`, `66`, `71/72`, `20+g/90+g + freq`, `10`) и выдаёт 5/6-байтовые кадры `[0x00, D..., 0xFF/0xFE]` на 400 Гц с 10-порядковым ФНЧ Баттерворта. | **100% обратная совместимость** |
| **ПРОВОДКА NG (DspCore)** | Начинает обмен с V2-кадра `CMD_HELLO` (`0xA5 0x5A ...`), получает возможности устройства и переходит в оптимизированный пакетный протокол V2 с CRC-16, адаптивной частотой дискретизации и гибким управлением АЦП/ЦОС. При подключении старого УСО ПК автоматически откатывается в legacy `uco32`. | **Автопереговоры V2 → Legacy fallback** |
| **Загрузчик USB (UBL1)** | Команды `A1` (`INFO`) и `08 12 34 56 78` (`BOOT → 08 AA`) полностью сохранены; приложение по-прежнему линкуется по `0x08008000`. | **100% совместимость с `uso32-bootloader.exe`** |

Переход обратно из V2 в режим автоопределения происходит мгновенно по команде V2 `CMD_STOP`, по классической команде `0x10` (отвечает `0x55`) или при разрыве USB CDC.

## 2. Формат кадров протокола V2

Все многобайтовые поля — **little-endian**. Максимальный размер кадра **63 байта** (строго меньше 64-байтового USB Full-Speed bulk endpoint — **без ZLP-задержек**).

```
[0..1]   magic        Host→USO: 0xA5, 0x5A  |  USO→Host: 0x5A, 0xA5
[2]      ver_flags    (2 << 4) | flags
[3]      msg_type     Тип команды / ответа / телеметрии
[4..5]   seq          uint16_t — счётчик последовательности
[6]      payload_len  uint8_t (0..54 байт)
[7..7+N-1] payload    Полезная нагрузка
[7+N..8+N] crc16      CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF) по байтам [0..7+N-1]
```

Байты `0xA5` и `0x5A` не используются ни в одной команде классического протокола — конфликты исключены.

### Команды V2

| Код | Имя | Назначение |
|---:|---|---|
| `0x01` | `CMD_HELLO` | Запрос идентификатора (`USO_DEVICE_NUMBER`), версии ПО (`3.0.0`), ID кристалла ADS1262, UID STM32, тактовой частоты АЦП (`7.3728 МГц` внутр. / `4.608 МГц` внешн.) и битовой маски возможностей. |
| `0x02` | `CMD_CONFIGURE` | Полная конфигурация тракта (несущая, режим частоты `AUTO` или ручной `DR`, децимация `1..16`, PGA `×1..×32` + bypass, фильтр `Sinc1..Sinc4/FIR`, `CHOP`, `VBIAS`, `INPMUX`, режим ФНЧ МК, срез ФВЧ, размер пакета `1..10`, автовосстановление). |
| `0x03` | `CMD_START` | Запуск потока V2 (опционально с 16-байтовым `uso_v2_config_t` в payload). Возвращает `RSP_START` с точными согласованными `effective_fs_dhz` и `hw_fs_dhz`. |
| `0x04` | `CMD_STOP` | Остановка потока, очистка очереди данных, возврат в режим автоопределения. |
| `0x05` | `CMD_SET_LIVE` | Безударное обновление усиления PGA, ФВЧ, ФНЧ и размера батча **на лету** без пересоздания сессии. |
| `0x06` | `CMD_GET_DIAG` | Снимок счётчиков диагностики: отсчёты, пропуски, missed DRDY, ошибки CRC/SPI/STALE, переполнения TX/RX, регистр `STATUS` АЦП. |
| `0x07` | `CMD_RECALIBRATE` | Аппаратная самокалибровка смещения (`SFOCAL1`) всех 6 ступеней усиления для активных `DR / фильтр / CHOP`, возвращает 6 измеренных 24-битных смещений. |
| `0x08` | `CMD_RESET_ADC` | Программный аппаратный сброс и повторная инициализация ADS1262 без переподключения питания платы. |

### Потоковый кадр телеметрии `MSG_DATA_BATCH (0x90)`

12-байтовый заголовок + до **10 отсчётов `int32_t`** = **52 байта payload → 61 байт на линии** (один USB FS bulk пакет, до **10×** меньше прерываний USB по сравнению со старым 6-байтовым потоком):

- `timestamp_ms (u32)` — метка времени МК (`HAL_GetTick`) последнего отсчёта в пакете.
- `first_sample_idx (u32)` — монотонный индекс первого отсчёта (мгновенное обнаружение потерь).
- `effective_fs_dhz (u16)` — фактическая частота дискретизации в единицах `0.1 Гц` (например, `2000` = `200.0 Гц`).
- `flags (u8)` — `PGA_OVF`, `ADC_ALARM`, `GAP_DROPPED`, `HPF_ACTIVE`, `LPF_ACTIVE`, `CHOP_ACTIVE`.
- `gain_and_count (u8)` — старшая тетрада: усиление `0..5`, младшая тетрада: число отсчётов `1..10`.

## 3. Адаптивный выбор частоты дискретизации (`DR = 0xFF AUTO`)

Подбирается минимальная аппаратная скорость ADS1262 с запасом по виртуальной сетке `26 × f_несущей` (`DLPOL_R = 13`):

| Несущая прибора | Внутр. ген. 7.3728 МГц | Внешн. X1 4.608 МГц (Rev P) | Выигрыш по шуму и USB |
|---|---|---|---|
| **16 Гц / 10 Гц** | `400 SPS` (`decim=1`) → **400 Гц** | `250 SPS` (`decim=1`) → **250 Гц** | Полная полоса для 16 Гц BPSK |
| **7 Гц / 5 Гц** | `400 SPS` (`decim=2`) → **200 Гц** | `250 SPS` (`decim=1`) → **250 Гц** | −3 дБ белого шума, вдвое меньше трафик |
| **3.6 Гц / 2.5 Гц** | `100 SPS` (`decim=1`) → **100 Гц** | `62.5 SPS` (`decim=1`) → **62.5 Гц** | Аппаратный Sinc4 100 SPS: ~0.10 µВrms + подавление 50 Гц |
| **1.8 Гц** | `60 SPS` (`decim=1`) → **60 Гц** | `62.5 SPS` (`decim=1`) → **62.5 Гц** | Глубокое аппаратное подавление помех |

## 4. Гибкая обработка сигнала

- **Режим `LPF = BYPASS` (по умолчанию в V2)**: передача линейно-фазового потока от аппаратного Sinc-фильтра ADS1262 напрямую в ПК `DspCore` (исключаются фазовые искажения 10-порядкового БИХ-фильтра перед КИХ и коррелятором RM(1,4)).
- **Режим `LPF = BUTTER4`**: расчёт 4-порядкового ФНЧ Баттерворта на лету методом билинейного преобразования для **любой** активной `Fs`.
- **Динамический ФВЧ (DC-blocker)**: пересчитывается под текущую `Fs` и срез `0.05..2.0 Гц` (или отключается `0 мГц`).
- **Разделение перегрузки PGA и фатальной аварии АЦП**: флаги `PGAD/PGAH/PGAL_ALM` (`STATUS[4:2]`) больше не останавливают АЦП до сброса питания, а передаются флагом `USO_V2_BATCH_PGA_OVF` (в legacy — маркером `0xFE`) для подсветки на осциллографе.
- **Диагностические входы (`INPMUX`)**: нормальный вход сейсмотрансформатора (`0x89`), внутреннее короткое замыкание (`0xFF`, проверка шумовой полки), датчик температуры кристалла (`0xBB`), контроль `AVDD`/`DVDD` (`0xCC`/`0xDD`).
